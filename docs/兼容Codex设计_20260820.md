# ByeByeCode Codex 兼容设计

最后更新时间：2026-08-21（北京时间）

## 1. 目标与范围

在不改变现有 Claude Code 默认行为的前提下，为 ByeByeCode 增加 Codex 原生兼容入口：

- 默认目标仍为 Claude Code。
- 通过 `--target codex` 显式选择 Codex。
- 通过 `--init` 初始化目标配置，通过 `--check` 验证环境，通过 `--wrap` 启动目标程序。
- 使用 Codex 官方支持的 `tui.status_line` 配置，不修改 Codex 本体。
- 继续复用现有配置、主题和状态栏核心模型，但隔离平台相关的路径、输入协议和启动逻辑。

本次不承诺将 Claude Code 的自定义段落直接注入 Codex footer。Codex 的 `tui.status_line` 只接受官方内置字段，`byebyecode_usage`、翻译和 Claude transcript 用量等自定义段落仍只在 Claude Code statusLine 流程中生效。

## 2. 命令接口

新增目标参数，默认值为 `claude`：

```text
byebyecode --init
byebyecode --init --target codex
byebyecode --check --target codex
byebyecode --print --target codex
byebyecode --wrap --target codex -- --model gpt-5.6
```

`--print --target codex` 只输出 ByeByeCode 目标配置和 Codex 的 `tui.status_line`，不输出 Codex 其他配置，避免暴露 provider 或 MCP 凭证。

行为约定：

- 未指定 `--target` 时保持现有 Claude 行为。
- `--target codex` 不会静默回退到 Claude。
- `--wrap` 后的参数原样透传给 `codex` 或 Windows 下的 `codex.cmd`。
- 子进程退出码、标准错误和中断行为向调用方透传。
- `--patch` 仅支持 Claude Code；Codex 目标下直接拒绝，绝不修改 Codex 安装文件。

## 3. 架构

### 3.1 目标抽象

新增 `Target` 枚举，至少包含 `Claude` 和 `Codex`。CLI 负责解析，业务入口按目标分发；平台差异不散落在状态栏段实现中。

### 3.2 配置存储

ByeByeCode 自身配置按目标隔离：

| 目标 | 配置目录 |
| --- | --- |
| Claude | `~/.claude/byebyecode/` |
| Codex | `~/.codex/byebyecode/` |

现有 TOML 配置和主题格式继续复用。配置加载器接收目标后计算路径，默认仍指向 Claude 路径。

### 3.3 Codex 配置适配器

新增独立的 Codex 配置适配器，负责 `~/.codex/config.toml`：

1. 使用 `toml_edit` 读取并修改文档，尽量保留注释、顺序和原格式。
2. 仅维护 `tui.status_line`。
3. 如果配置文件不存在，创建最小合法文件并写入推荐字段。
4. 如果文件存在，任何写入前都创建带时间戳的同目录备份。
5. 如果已经存在 `tui.status_line`，覆盖为 ByeByeCode 推荐字段并提示；重复执行结果保持一致。
6. 不修改模型、权限、沙箱、MCP、主题、终端标题等其他设置。

推荐字段使用 Codex 官方内置 ID，例如 `model-with-reasoning`、`context-remaining`、`current-dir` 和 `git-branch`；具体可用 ID 以实现时读取的官方配置文档为准。

### 3.4 启动适配器

新增目标程序查找和启动接口：

- Claude：保留现有查找逻辑。
- Codex：优先查找 PATH 中的 `codex`；Windows 额外查找 `codex.cmd`。
- 找不到目标程序时返回明确错误，不进行跨目标回退。

## 4. 配置写入流程

```text
解析 CLI
  -> 判断 Target
  -> Codex: 定位 ~/.codex/config.toml
  -> 解析 TOML
  -> 检查 tui.status_line
       ├─ 已存在：备份 -> 覆盖字段 -> 原子替换
       └─ 不存在：创建最小配置 -> 原子替换
```

写入失败时保留原文件和备份文件，不产生半写入配置。备份文件名包含北京时间日期时间，避免覆盖历史备份。

## 5. 错误处理

- CLI 目标值非法：由 `clap` 报错，不执行文件写入。
- Codex 不在 PATH：`--check` 和 `--wrap` 返回安装/路径提示。
- Codex TOML 非法：报告解析错误和位置，拒绝修改。
- `tui.status_line` 类型非法：报告期望类型为字符串数组；合法数组（包括空数组）会被覆盖，拒绝修改非法 TOML 或标量值。
- 文件权限或原子替换失败：保留原文件，返回具体路径和系统错误。
- Codex 子进程失败：透传退出码和 stderr。
- Claude 分支的现有错误处理和 JSON stdin 解析保持不变。

## 6. 安全修复

`.mcp.json` 当前包含硬编码 `MCPR_TOKEN`。本次移除仓库中的明文令牌，改为要求运行环境提供 `MCPR_TOKEN`，配置文件不再保存凭证。README 和本文件只记录环境变量名称，不记录实际值。

令牌在 MCP Router 服务侧的吊销/轮换需要对应服务权限；代码仓库改动只负责消除明文泄露和阻止后续提交再次携带该值，不虚报已完成服务侧吊销。

## 7. 测试与验收

### 单元测试

- 默认目标为 Claude，显式 `codex` 可正确解析，未知目标被拒绝。
- Codex 配置不存在、缺少 `status_line`、已有数组/空数组和非法类型。
- 已有字段会在备份后被覆盖，重复初始化结果一致且不会修改其他字段。
- Windows `codex.cmd` 和 Unix `codex` 查找。
- 临时文件失败或 TOML 解析失败不会损坏原文件。

### 回归测试

- Claude 默认初始化和 Claude settings.json 自动配置。
- Claude JSON stdin 状态栏输出和主题加载。
- 目标程序退出码与参数透传。
- `.mcp.json` 不再包含 `MCPR_TOKEN` 的字面量凭证。

### 验证命令

```powershell
cargo fmt --all -- --check
cargo test
cargo clippy --all-targets --all-features -- -D warnings
```

Windows 环境至少执行一次完整 `cargo test`；文档、代码和测试在同一变更中更新。

### Windows 实测结果

- 使用 Rust `1.97.1` 的 `stable-x86_64-pc-windows-msvc` 工具链完成构建。
- 使用 Visual Studio 2022 Build Tools `17.14.39` 的 x64 C++ 编译器和 Windows SDK 完成链接。
- `cargo test` 通过，9 项测试全部成功。
- `cargo fmt --all -- --check` 通过。
- `cargo clippy --all-targets --all-features -- -D warnings` 通过，0 警告。
- `byebyecode --target codex --wrap -- --version` 成功调用 Windows `codex.cmd`，参数与退出码透传正常。
- 冒烟验证未执行 `--init`，没有修改用户现有的 `~/.codex/config.toml`。

## 8. 交付边界

本设计完成后再进入实现。实现阶段只修改与目标分发、Codex 配置、启动查找、安全配置和对应文档/测试直接相关的文件，不重构无关状态栏段，不修改远程服务器文件，也不自动创建或合并 Pull Request。
